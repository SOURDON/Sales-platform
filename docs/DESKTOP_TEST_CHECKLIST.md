# Чеклист тестов десктоп-приложения

Проверка на **трёх разных ПК** (желательно: 1× macOS, 2× Windows или наоборот). На каждом ПК — своя роль из таблицы.

**Перед тестом:** установленный билд из `desktop/npm run build`, backend доступен по `VITE_API_URL`, учётные записи всех ролей.

## Общее (все роли)

- [ ] Установка без ошибок, приложение запускается
- [ ] Вход логин/пароль, главная загружается
- [ ] Баннер «Нет сети» при отключении Wi‑Fi / кабеля
- [ ] После включения сети баннер «Синхронизация…», затем исчезает
- [ ] Выход и повторный вход — сессия по «Запомнить меня» (если включено)

## ПК 1 — ADMIN

- [ ] Офлайн: открыть точку, товары, смену — данные из кэша видны
- [ ] Офлайн: добавить продажу → в списке сразу (optimistic)
- [ ] Офлайн: списание / открытие или закрытие смены (по сценарию точки)
- [ ] Онлайн: очередь ушла, те же данные в **веб-версии** в браузере
- [ ] Повторная отправка той же продажи не создаёт дубль (`saleId`)

## ПК 2 — DIRECTOR или ACCOUNTANT

- [ ] Офлайн: дашборд / финансы открываются из кэша
- [ ] Офлайн: доход или расход → в очереди, отображается локально
- [ ] Офлайн (директор): сохранить план выручки на день → в кэше
- [ ] Онлайн: операции на сервере, веб совпадает

## ПК 3 — MANAGER

- [ ] Офлайн: главная (сводка, блок планов выручки) из кэша
- [ ] Онлайн: обновление главной после синхронизации других ролей (планы)

## Регрессия веба (быстро)

- [ ] В браузере без Tauri: продажи админа по-прежнему через localStorage-очередь (не сломана)
- [ ] Вход и основные экраны веба без изменений
